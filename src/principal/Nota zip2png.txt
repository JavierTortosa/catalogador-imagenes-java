Plan de Implementación — Editor Central Multi-Capa
Objetivo
Al activar el botón Collage (CMD_PREVIEW_RENDER_COLLAGE):

Ocultar el grid central y mostrar un editor central con lienzo grande
Mover las toolbars de capas al EAST del editor
El preview derecho se mantiene intacto como punto de entrada rápido
La galería ZIP alimenta al preview; desde preview se añaden capas al editor
Fase 1: Estructura del Editor Central
1.1. Nuevo panel CollageEditorPanel (en vista/panels/render/)

JPanel con BorderLayout
CENTER: JScrollPane con un JPanel lienzo (CollageCanvas) donde se pintan las capas superpuestas
NORTH: Toolbar propia del editor (alineación, auto-layout, tamaño lienzo)
EAST: Contenedor para las toolbars layerorderpreview + layerloadpreview
Tamaño mínimo del lienzo: 800×600 (configurable por inputs en toolbar)
1.2. CollageCanvas (en vista/panels/render/)

Extiende JPanel (o JComponent)
Pinta las capas en orden (fondo → frente) con sus zoom/offset individuales
Hit testing: detecta qué capa está bajo el cursor al hacer clic → la selecciona
Zoom/pan propio del canvas (independiente del preview)
1.3. Integración en RenderPanel

Añadir CollageEditorPanel como una card más en el panel central (junto a gridCardPanel)
showGridCard() se amplía a showCenterCard(String) con valores "grid", "collage"
Al activar Collage: ocultar gridCardPanel, mostrar collagePanel
Al desactivar Collage: ocultar collagePanel, mostrar gridCardPanel
Fase 2: Toolbars y Controles del Editor
2.1. Toolbar del editor (NORTH del CollageEditorPanel)

Grupo D-Pad 9 posiciones (3×3): alinea la capa seleccionada a cualquier posición del lienzo (usando DPadComponent.createGridLayout(3, 3) con 9 hotspots)
TOP_LEFT, TOP_CENTER, TOP_RIGHT
MIDDLE_LEFT, CENTER, MIDDLE_RIGHT
BOTTOM_LEFT, BOTTOM_CENTER, BOTTOM_RIGHT
Grupo Auto-layout: botones para distribuir capas en cuadrícula, fila, columna, etc.
Grupo Tamaño lienzo: JTextField ancho × alto + botón "Ajustar al contenido"
Grupo Zoom canvas: acercar/alejar/encajar
2.2. Toolbars layerorderpreview y layerloadpreview

Actualmente en EAST del rightPanel
Al activar Collage: se mueven al EAST del CollageEditorPanel
Al desactivar Collage: vuelven al EAST del rightPanel
Implementación: ComponentRegistry permite recolocar los componentes, o simplemente cambiar el parent añadiendo/quitando
Fase 3: Flujo de Capas
3.1. Añadir capa desde preview

El botón actual "Añadir capa" (CMD_LOAD_LAYER) se modifica:
Si Collage activo: captura la imagen del visor 2D (panel.get2DImage()) y la añade al CollageCanvas como nueva capa
Si Collage inactivo: comportamiento actual (extraer del ZIP)
La galería ZIP selecciona miniaturas → se cargan en preview → desde preview se añaden al editor
3.2. Enviar collage a preview

Botón "Enviar a preview" (o al desactivar Collage):
Rasteriza el lienzo del CollageCanvas (todas las capas compuestas) a una BufferedImage
La coloca en el visor 2D del panel derecho
El usuario decide si la asigna al grid central con "Asignar preview"
3.3. Pestaña "Capas" mejorada (tipo Photoshop)

JList<ImageLayer> con ListCellRenderer personalizado:
Thumbnail pequeño (32×32) de la capa
Nombre de la capa
Checkbox de visibilidad
Click en el CollageCanvas sobre una capa → se selecciona en la lista
Los botones de layerorderpreview (subir, bajar, frente, fondo) actúan sobre la selección

================================================================================
  ZIP2PNG — Generación automática de thumbnails para archivos 3D sin imagen
================================================================================

OBJETIVO
--------
Que la aplicación pueda generar una imagen PNG a partir de un archivo 3D (STL,
OBJ, 3MF) cuando este no tenga una imagen asociada, permitiendo visualizar el
contenido aunque el modelo esté comprimido en ZIP/RAR/7z (incluyendo multi-
volumen).

ARQUITECTURA GENERAL
--------------------

    Interface: ModelRenderer
    ├── AwtModelRenderer       (✔ siempre disponible, 0 dependencias)
    ├── JavaFxModelRenderer    (si JavaFX está en classpath)
    ├── OpenScadRenderer       (si existe tools/openscad/openscad.exe)
    └── BlenderRenderer        (si la ruta está configurada)

    RenderEngineManager:
      - Al arrancar, registra los renderers disponibles
      - Devuelve el motor activo según configuración
      - Fallback: si el motor configurado falla, usa AwtModelRenderer

SELECCIÓN DEL MOTOR (Configurador Avanzado)
--------------------------------------------
Sección nueva "Renderizado" en el panel de configuración avanzada:

  Motor por defecto: [AWT ▼]   ← desplegable con los disponibles
    ⬤ AWT (siempre disponible - recomendado)
    ○ OpenSCAD (requiere ruta)
    ○ Blender (requiere ruta)

  Ruta OpenSCAD: [___________] [Examinar...]
  Ruta Blender:  [___________] [Examinar...]

  Límite descompresión: [512] MB
  Carpeta temporal:     [___________] [Examinar...]
  [✔] Ignorar límite de MB

COMPARATIVA DE MOTORES
-----------------------

  Motor      Calidad  Dep. externa  Peso añadido  Se rompe si...
  ──────     ───────  ────────────  ────────────  ──────────────
  AWT        4/10     ninguna       0             nunca (código propio)
  JavaFX     8/10     JavaFX SDK    ~0 (dep. Mav. opc.)  API JavaFX cambia
  OpenSCAD   7/10     openscad.exe  28MB en /tools/       CLI OpenSCAD cambia
  Blender   10/10     blender.exe   externo (no incluir)  ruta perdida

  RECOMENDACIÓN: AWT puro para empezar. Interfaz limpia para migrar después.

MOTOR AWT (software renderer en Java puro ~500 líneas)
-------------------------------------------------------
  Clases:
    servici├│s/renderer/AwtModelRenderer.java
    servici├│s/renderer/StlParser.java

  Algoritmo:
    1. StlParser.parse(file) → List<Triangle> con vértices 3D + normal
    2. Calcular centro de la malla y escalar para que quepa en 512x512
    3. Rotar 30° en X, -45° en Y (vista isométrica)
    4. Para cada triángulo:
       a. Calcular intensidad de luz = dot(normal, vectorLuz)
       b. Color gris = intensidad * 200 + 55
       c. Proyectar vértices 3D → 2D
       d. Graphics2D.fillPolygon() con z-buffer
    5. Resultado: BufferedImage 512x512, fondo blanco

  Calidad: similar a thumbnails técnicos de Thingiverse/Printables
  No necesita: JavaFX, OpenSCAD, ni ninguna librería externa

MULTIVOLUMEN
------------
  - En la lista del Zip2PNG se agrupan como una sola entrada:
    ej: coleccion_piezas.part1.rar  ← (multivolumen, 3 partes)
    ej: trofeo_campeon.7z.001       ← (multivolumen, 2 partes)
    ej: escudo_final.zip             ← (normal)
  - Para extraer/renderizar: se pasa el primer volumen a 7z

LÍMITE DE MB
------------
  - Si el archivo supera el límite configurado → icono ⚠️ + tamaño en rojo
  - Al intentar procesar → diálogo:
    "El archivo X pesa Y MB, superando el límite de Z MB.
     ¿Quieres procesarlo igualmente bajo tu responsabilidad?"
    Opciones: [Procesar esta vez] [Procesar siempre] [Saltar]
  - Checkbox "Ignorar límite" en el configurador elimina la advertencia

ALMACENAMIENTO DE RESULTADOS
----------------------------
  1. Los PNGs generados se guardan primero en CARPETA TEMPORAL (configurable)
  2. El usuario revisa en el panel Zip2PNG (grid + preview)
  3. Al dar visto bueno → "Copiar a carpeta origen" (junto al archivo 3D)
     o a la ubicación que el usuario elija

    Así no se ensucia la carpeta del usuario hasta que él decida.

DETECCIÓN DE ARCHIVOS SIN IMAGEN
----------------------------------
  - El escáner recorre la carpeta actual (o las del proyecto)
  - Para cada archivo 3D sin un PNG/JPG/BMP/GIF asociado → lo añade a la lista
  - Asociación: mismo nombre, extensión diferente
    ej: modelo.stl → busca modelo.png, modelo.jpg...

MODO AUTOMÁTICO (2 fases)
--------------------------
  Fase 1 — Imágenes internas:
    Si el ZIP contiene imágenes (PNG/JPG), se muestran en grid + preview
    para que el usuario seleccione cuál usar.

  Fase 2 — Renderizado:
    Si no hay imágenes internas, se selecciona el STL más grande y se renderiza
    con el motor activo. El usuario puede modificar después.

UI DEL PANEL ZIP2PNG
---------------------
  - Grid central con los archivos procesados
  - Panel derecho con preview ampliado
  - Botones:
    [Copiar a carpeta origen]  [Copiar a...]  [Abrir carpeta temporal]
    [Regenerar]  [Seleccionar otro STL interno]
